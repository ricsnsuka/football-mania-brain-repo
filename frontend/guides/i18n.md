# i18n Guide

## Stack

- `i18next` v26 + `react-i18next`
- Initialized in `src/lib/i18n.ts`
- Locale files: `src/locales/<lang>/<namespace>.json`
- Supported languages: `en` (primary), `pt`, `es`

## Loading strategy — `en` is bundled, the rest are lazy

`en/common.json` is imported statically into `src/lib/i18n.ts` and passed as `resources`.
Every other language loads on demand through `i18next-resources-to-backend`.

This is not a performance tweak; it fixes a correctness bug. Pages are prerendered at build
time, where i18next resolves the dynamic import and emits **translated** HTML. On the client
that same import is still in flight during hydration, and because `useSuspense` is `false`
the first client render produces **raw keys**. React found text where the server had put
different text and threw a hydration mismatch (#418) on every production page load — and
users saw `footer.theme` and `login.title` flash before the chunk landed.

Two consequences worth knowing:

- **`partialBundledLanguages: true` is mandatory.** With `resources` and a backend both
  configured, i18next otherwise treats the bundled set as complete and never requests `pt`
  or `es` — the language switcher silently stops working.
- **A new default-language namespace is not automatically bundled.** Only `common` is. Either
  import the new namespace alongside `enCommon` or accept that it loads lazily and can flash
  keys on first paint.

Switching language happens well after hydration, so lazy-loading `pt`/`es` mismatches
nothing. Bundling costs ~28KB in the main chunk.

## Usage

```tsx
'use client';
import { useTranslation } from 'react-i18next';

export function MyComponent() {
  const { t } = useTranslation('players');
  return <h1>{t('list.title')}</h1>;
}
```

## Adding a New Key

1. Add the key to `src/locales/en/<namespace>.json`
2. Add the **same key** to `src/locales/pt/<namespace>.json` and `src/locales/es/<namespace>.json`
3. Use `t('namespace.key')` in the component

## Namespace Convention

One namespace per feature — named after the feature:

| Feature | Namespace | File |
|---------|-----------|------|
| Shared/global | `common` | `common.json` |
| Players | `players` | `players.json` |
| Matches | `matches` | `matches.json` |

## Key Naming

- `camelCase` dot-notation: `player.card.title`, `match.status.live`
- Plurals: `player.count_one`, `player.count_other`
- Interpolation: `"welcome": "Hello, {{name}}"` → `t('welcome', { name })`

## Rules

- All user-facing strings must use `t()` — no hardcoded text in JSX
- Keys must be identical across all locale files
- `useTranslation` requires a Client Component (`'use client'`)
